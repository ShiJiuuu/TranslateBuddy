# 在网页端 Dify 上调试 TranslateBuddy（M1 / docx + xlsx）

适用两种情况，步骤 95% 相同：

| 你的 Dify | 判断 | 差异 |
|---|---|---|
| 自建（服务器 docker compose，浏览器访问） | 你能拿到 `dify/docker` 目录 | 装本地包要关签名校验；大文件要改 `.env` |
| Dify Cloud（cloud.dify.ai） | 只能通过网页操作 | 不能改 `.env`，大文件受限；本地包可直接装 |

**第一次联调不需要改任何 `.env`**：默认 15 MB 上传 / 600 s 调用，测几页的 docx / xlsx 完全够。

---

## 1. 拿到安装包

仓库里已经打好：`dist/translate_buddy-0.0.3.difypkg`（约 20 KB）。

改了代码后重新打包并校验：

```bash
python scripts/package.py                                  # dist/translate_buddy-<version>.difypkg
python scripts/validate_package.py dist/translate_buddy-0.0.3.difypkg
```

> 资源（图标）必须放在包内 `_assets/` 下，YAML 里写相对路径（`icon.svg`）。这是 plugin_daemon 的约定，放错位置安装时会报 `file not found: icon.svg`。

包里只含 `manifest.yaml / main.py / _assets / requirements.txt / provider / tools / backend`，不含测试和 `.venv`。

## 2. 安装插件

控制台右上角 **Plugins / 插件** → **安装插件** → **本地文件**（Local Package File）→ 选 `.difypkg` → 确认权限（Tool、Model/LLM）。

可能遇到的两种报错：

| 报错 | 原因 | 处理 |
|---|---|---|
| `file not found: icon.svg` / `failed to remap assets` | 图标没放在包内 `_assets/` 下 | 用最新 `scripts/package.py` 重新打包（会带上 `_assets`），并跑 `validate_package.py` 自检 |
| `plugin_unique_identifier is not valid` | `manifest.yaml` 与 `provider/*.yaml` 里的 `author` 和你的 GitHub handle 不一致 | 两处 `author` 都改成你的 GitHub 用户名，重新打包 |
| `signature verification failed` | 自建实例默认校验包签名（`FORCE_VERIFYING_SIGNATURE=true`） | 自建：`.env` 设 `FORCE_VERIFYING_SIGNATURE=false`，`docker compose up -d` 重建 `plugin_daemon`。Cloud 的本地包入口一般不做这项校验；若仍报错，只能走签名流程 |

## 3. 准备一个模型

本插件的 `model` 参数是 `model-selector`，**下拉里必须是工作区已经配好的模型**。

- 设置 → 模型供应商 → 确认至少有一个可用 LLM（OpenAI 兼容、通义、DeepSeek 等）。
- 没有的话先加一个，否则工具节点里选不到模型。

## 4. 建一个最小工作流

**工作室 → 创建空白应用 → 工作流**：

1. **开始**节点：加一个文件变量，比如 `doc`，类型 File（允许 docx / xlsx）。
2. **工具**节点：搜索 `翻译文档 / Translate document`，填写：
   - `file`：绑定开始节点的 `doc`
   - `target_lang`：zh-Hans（或 en）
   - `source_lang`：auto
   - `model`：选一个工作区模型
   - `glossary`、`output_name`：留空
3. **结束**节点：输出变量加两个——
   - `files` → 选工具节点的 `files`（这是要下载的译文文件）
   - `text` → 选工具节点的 `text`（翻译摘要）

> 不同版本 End 节点的按钮文案略有差异，找「输出变量 / Output variables」即可。

## 5. 跑一次

上传一个**带格式的 docx**（最好含加粗、表格、页眉页脚），运行。

预期：

- 结束节点能下载到 `原名.zh-Hans.docx`；
- 页面上的 text 类似 `完成：13/13 段已翻译，耗时 12.4s`；
- json 里有 `segments / translated / kept_source / format_fallback / qa_issues`。

打开输出文件检查三件事：

1. 文字变成中文；
2. 加粗/颜色/斜体还在；
3. 表格、页眉页脚、图片没动。

**xlsx** 用同一个节点，上传表格即可。预期：文字变中文，数字、公式、合并单元格、填充色、数字格式不变。

## 6. 大文档：三节点分片工作流

超过 50 页、或者想中断续跑时，换成三个节点。

```
开始(doc) → 解析文档 → 迭代 → 回写文档 → 结束(files)
                │         └─ 翻译分片(job_id, item.index, model)
                └─ 输出 json.job_id / json.shards
```

1. **解析文档**：`file` 绑 `doc`，选目标语言；有术语表就在 `glossary` 传 CSV。
   输出 json 里有 `job_id`、`shard_count`、`shards: [{index, segments, chars}]`。
2. **迭代节点**：输入数组选「解析文档」的 `json.shards`；迭代体内放 **翻译分片**：
   - `job_id` = 解析文档的 `json.job_id`
   - `shard_index` = 迭代变量 `item.index`
   - `model` = 选模型
3. **回写文档**：`job_id` 传解析文档的 `json.job_id`，结束节点输出它的 `files`。

特点：

- 每片 15–30 s，不会撞 600 s 上限；
- 重跑同一片会命中缓存（`cached: true`），不重复花钱；
- 作业存在插件的 `/app/storage/translate_buddy/jobs`，保留 24 小时。

## 7. 错误对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `E_UNSUPPORTED_FORMAT: .pdf …` | pdf / doc / xls 还没做 | 换 docx / xlsx；pdf 在 M2、doc/xls 在 M4 |
| `缺少 file 参数` | 工具节点的 file 没绑定 | 回到节点里绑定开始节点的文件变量 |
| 输出文件是空的 / 0 段 | 文档可能是扫描件或全图片 | 换一个文本型 docx |
| `需要选择一个模型` | model 参数没选 | 选一个工作区模型 |
| 跑很久最后超时 | 单次调用超 600 s（Cloud 默认） | 换小文件；大文件要改 `PLUGIN_MAX_EXECUTION_TIMEOUT`（自建） |
| 安装时 pip 失败 | daemon 装依赖时访问不了 PyPI | 自建：设 `PIP_MIRROR_URL` 后重装插件 |

## 8. 什么时候才需要改 `.env`

只有这三件事需要（自建才行，Cloud 改不了）：

- 上传 **> 15 MB** 的文档；
- 输出 **> 50 MB**；
- 单次翻译 **> 600 s**（大约 50 页以上）。

自建实例跑：

```bash
python scripts/setup_dify_env.py /path/to/dify/docker
cd /path/to/dify/docker && docker compose up -d
```

7 项配置和原因见 [方案.md](方案.md) 第 7.1 节。

## 9. 可选：远程调试（改代码即生效）

不想每次打包上传，可以让本地进程连到 Dify 的 plugin_daemon 调试口（5003）：

```bash
pip install dify-plugin
dify plugin init          # 或在现有目录生成 .env
# .env 填远端地址与调试 key，然后：
dify plugin run
```

前提：**5003 端口对你可达**（自建服务器且防火墙放行）。Cloud 用不了这条路——它没有对你暴露的调试口。

## 10. 这一版没做的

- pdf / xlsx / doc / xls（M1–M4）
- 术语表虽然参数在，但只进提示词、还没做占位符锁定（M1）
- 大文档分片（M3）：现在是单次调用，页数多了会撞 600 s
